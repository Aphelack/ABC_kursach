# Quick Start Guide - Random Forest Benchmark

## Installation (3 minutes)

```bash
# 1. Install dependencies
sudo apt-get install build-essential cmake python3 python3-pip
pip3 install -r requirements.txt

# 2. Build the project
./build.sh
```

## Run Your First Benchmark (1 minute)

```bash
# Option 1: Quick run with auto-visualization
./run_benchmark.sh

# Option 2: Manual run
./build/rf_benchmark
python3 visualize_single.py rf_benchmark_*.json
```

## Compare Two Processors

### On First Computer (e.g., your laptop):
```bash
./build/rf_benchmark
# Copy the generated JSON file: rf_benchmark_<CPU1>_<timestamp>.json
```

### On Second Computer (e.g., server):
```bash
./build/rf_benchmark
# Copy the generated JSON file: rf_benchmark_<CPU2>_<timestamp>.json
```

### Compare Results:
```bash
# Transfer both JSON files to one machine, then:
python3 compare_processors.py \
    rf_benchmark_<CPU1>_<timestamp>.json \
    rf_benchmark_<CPU2>_<timestamp>.json
```

## Customize Benchmark

Edit `src/main.cpp` around line 30:

```cpp
// Test different tree counts
config.n_estimators = {50, 100, 200, 500};

// Increase tree depth
config.max_depth = 30;

// More runs for statistical significance
config.num_runs = 5;

// Use specific thread count
config.n_threads = 8;  // or -1 for all cores
```

Then rebuild:
```bash
./build.sh
```

## Use Your Own Dataset

Create CSV file with format:
```
feature1,feature2,feature3,...,label
1.2,3.4,5.6,...,0
2.3,4.5,6.7,...,1
...
```

Run benchmark:
```bash
./build/rf_benchmark path/to/your_data.csv
```

## Output Files

- **JSON Report**: `rf_benchmark_<CPU_NAME>_<TIMESTAMP>.json`
  - Contains all benchmark data
  - Portable across machines
  - CPU name automatically included

- **Visualization**: `benchmark_visualization_<CPU_NAME>.png`
  - Generated by `visualize_single.py`
  - Comprehensive analysis plots

- **Comparison**: `benchmark_comparison_<CPU1>_vs_<CPU2>.png`
  - Generated by `compare_processors.py`
  - Side-by-side performance analysis

## Understanding Results

### Key Metrics:

1. **Training Time**: Lower is better
2. **Accuracy**: Higher is better (0-100%)
3. **CPU Usage**: Higher = better core utilization
4. **Efficiency**: Accuracy / Time (higher is better)
5. **Speedup**: CPU1 time / CPU2 time (>1 means CPU1 is faster)

### What to Look For:

- **Linear scaling**: Time should increase linearly with trees
- **CPU saturation**: >90% usage means good parallelization
- **Core balance**: All cores should show similar usage
- **Consistency**: Low std deviation across runs

## Troubleshooting

### "CMake not found"
```bash
sudo apt-get install cmake
```

### "No module named 'matplotlib'"
```bash
pip3 install -r requirements.txt
```

### "Low CPU usage"
- Dataset too small → use larger dataset or synthetic data
- Not enough cores → expected for small datasets

### "Build errors"
- Check C++ compiler version (need C++17)
- GCC 7+ or Clang 5+
