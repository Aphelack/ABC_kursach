# 4.1 Постановка задачи для программного обеспечения

Анализ производительности – ключевой момент данного курсового проекта. Он производится путем временной оценки выполнения программного обеспечения для алгоритма Random Forest (случайный лес) на задаче классификации мошеннических транзакций. Алгоритм Random Forest был предложен Лео Брейманом в 2001 году как развитие идей бэггинга и случайных деревьев решений. Его основная цель – создание высокоточных классификаторов путем комбинирования множества деревьев решений, обученных на различных подвыборках данных. Этот алгоритм стал одним из наиболее эффективных методов машинного обучения и широко применяется в финансовой аналитике, медицинской диагностике, обнаружении аномалий и других областях, требующих высокой точности предсказаний.

## Временная сложность алгоритма

Временная сложность обучения Random Forest определяется следующими факторами:

**Для одного дерева решений:**
- Построение дерева глубины $d$ на выборке из $n$ образцов с $m$ признаками требует $O(n \cdot m \cdot \log n)$ операций в среднем случае
- Поиск оптимального разбиения в узле: $O(n \cdot m)$ для рассмотрения всех признаков и порогов
- Ограничение на количество порогов (50 в данной реализации) снижает сложность до $O(n \cdot m \cdot k)$, где $k = 50$

**Для ансамбля из $T$ деревьев:**

$$T_{train} = O(T \cdot n \cdot m \cdot \log n)$$

При параллелизации на $p$ процессорах:

$$T_{parallel} = O\left(\frac{T}{p} \cdot n \cdot m \cdot \log n\right)$$

**Сложность предсказания:**

Для классификации одного образца требуется пройти от корня до листа в каждом из $T$ деревьев глубины $d$:

$$T_{predict} = O(T \cdot d)$$

**Пространственная сложность:**

Память для хранения леса из $T$ деревьев, каждое с максимум $2^d$ узлами:

$$S = O(T \cdot 2^d)$$

Для обучения требуется дополнительно хранить bootstrap-выборки:

$$S_{train} = O(n \cdot m + T \cdot 2^d)$$

## Формальное описание алгоритма Random Forest

**Алгоритм обучения:**

1. **Инициализация.** Задать количество деревьев $T$, максимальную глубину $d$, количество признаков для каждого разбиения $m' = \sqrt{m}$.

2. **Для каждого дерева** $t = 1, 2, \ldots, T$:
   - Создать bootstrap-выборку размера $n$ с возвращением из обучающего набора
   - Построить дерево решений рекурсивно:
     - В каждом узле случайно выбрать $m'$ признаков из $m$ доступных
     - Найти оптимальное разбиение по критерию Джини среди выбранных признаков
     - Разделить узел на два дочерних узла
     - Повторять до достижения максимальной глубины или критерия остановки

3. **Параллелизация.** Распределить деревья между $p$ потоками для одновременного обучения на многоядерном процессоре.

**Алгоритм классификации:**

1. Для нового образца $\mathbf{x}$ получить предсказание от каждого дерева $t$: $h_t(\mathbf{x})$

2. Применить голосование большинством:

$$H(\mathbf{x}) = \arg\max_{c} \sum_{t=1}^{T} \mathbb{1}[h_t(\mathbf{x}) = c]$$

где $\mathbb{1}[\cdot]$ — индикаторная функция.

- **Несбалансированность классов:** требует использования специальных метрик (F1-score) и стратифицированной выборки

Программная реализация позволяет точно измерить производительность процессора при выполнении типичных задач машинного обучения с использованием параллельных вычислений на многоядерных архитектурах.

# 4.2 Обоснование и описание функций программного обеспечения

## 4.2.1 Алгоритм Random Forest (Случайный лес)

### Принцип работы алгоритма Random Forest

Random Forest (случайный лес) — это ансамблевый алгоритм машинного обучения, основанный на методе бэггинга (bootstrap aggregating) и использующий множество деревьев решений для выполнения задач классификации и регрессии. Алгоритм работает по следующему принципу:

**Этап 1: Bootstrap-выборка.** Для каждого дерева в лесу создается случайная выборка данных с возвращением (bootstrap sample) из исходного обучающего набора. Это означает, что некоторые наблюдения могут повторяться в выборке, а некоторые — отсутствовать. Размер bootstrap-выборки равен размеру исходного набора данных.

**Этап 2: Случайный выбор признаков.** При построении каждого узла дерева решений рассматривается не весь набор признаков, а случайное подмножество размером √n, где n — общее количество признаков. Это обеспечивает разнообразие деревьев и снижает корреляцию между ними.

**Этап 3: Построение дерева решений.** Каждое дерево строится до максимальной глубины без обрезки (pruning) или до достижения заданных критериев остановки (минимальное количество образцов в узле, максимальная глубина). Для выбора наилучшего разбиения в каждом узле используется критерий Джини (Gini impurity):

$$\text{Gini} = 1 - \sum_{i=1}^{C} p_i^2$$

где $p_i$ — доля образцов класса $i$ в узле, $C$ — количество классов.

**Этап 4: Агрегация предсказаний.** Для классификации окончательное предсказание формируется путем голосования большинством (majority voting) среди всех деревьев в лесу. Класс, набравший наибольшее количество голосов, выбирается как итоговое предсказание.

Преимущества алгоритма: высокая точность, устойчивость к переобучению, способность обрабатывать большие объемы данных с высокой размерностью, возможность параллельного обучения деревьев.

## 4.2.2 Функция fit (обучение Random Forest)

Данная функция реализует параллельное обучение ансамбля деревьев решений на заданном наборе данных. Описание функции можно представить следующим образом:

```cpp
void RandomForest::fit(const Matrix& X, const Labels& y)
```

Функция принимает матрицу признаков `X` размером [n_samples × n_features] и вектор меток классов `y` размером [n_samples]. Процесс обучения организован следующим образом:

1. **Инициализация параметров.** Вычисляется количество признаков для каждого дерева по формуле `max_features = √n_features`, что является стандартной практикой для задач классификации и обеспечивает оптимальный баланс между разнообразием деревьев и их предсказательной способностью.

2. **Параллелизация обучения.** Деревья распределяются равномерно между потоками для параллельного обучения. Количество потоков определяется параметром `n_threads_` или автоматически устанавливается равным количеству доступных логических ядер процессора. Вычисляется количество деревьев на поток:
   
   $$\text{trees\_per\_thread} = \lceil \frac{n\_estimators}{n\_threads} \rceil$$

3. **Инициализация генератора случайных чисел.** Для каждого потока устанавливается уникальное начальное значение (seed) по формуле: `random_state + thread_id × 1000`, что обеспечивает воспроизводимость результатов при сохранении случайности между деревьями.

4. **Создание и обучение деревьев.** Для каждого дерева в диапазоне потока вызывается функция `fit_tree()`, которая выполняет bootstrap-выборку, выбор случайных признаков и построение дерева решений.

5. **Синхронизация потоков.** После завершения обучения всех деревьев выполняется ожидание завершения всех потоков с помощью метода `join()`, что гарантирует завершение параллельных вычислений перед возвратом управления.

Такой подход позволяет эффективно использовать многоядерную архитектуру современных процессоров и значительно сокращает время обучения модели, особенно при большом количестве деревьев в ансамбле.

## 4.2.3 Функция fit_tree (обучение одного дерева решений)

Функция реализует обучение отдельного дерева в ансамбле Random Forest с применением bootstrap-выборки и случайного выбора признаков:

```cpp
void RandomForest::fit_tree(size_t tree_idx, const Matrix& X, const Labels& y, 
                            size_t n_samples, size_t n_features)
```

Процесс обучения одного дерева организован следующим образом:

1. **Bootstrap-выборка данных.** Создается случайная выборка индексов размером `n_samples` с возвращением. Это означает, что некоторые образцы из исходного набора могут встречаться несколько раз, а другие — не попасть в выборку (в среднем, около 63.2% уникальных образцов попадает в каждую bootstrap-выборку).

2. **Формирование обучающей выборки.** На основе полученных индексов создаются новые матрица признаков `X_bootstrap` и вектор меток `y_bootstrap`. Используется резервирование памяти (`reserve()`) для оптимизации производительности.

3. **Случайный выбор подмножества признаков.** Вызывается функция `select_features()`, которая случайным образом выбирает `max_features` признаков из всего набора. Это обеспечивает декорреляцию между деревьями и повышает обобщающую способность модели.

4. **Создание и обучение дерева.** Создается объект `DecisionTree` с заданными параметрами `max_depth` (максимальная глубина), минимальным количеством образцов для разбиения и количеством рассматриваемых признаков. Затем вызывается метод `fit()` дерева с передачей bootstrap-выборки и подмножества признаков.

Такая организация обеспечивает создание разнообразных деревьев в ансамбле, что является ключевым фактором эффективности алгоритма Random Forest.

## 4.2.4 Функция find_best_split (поиск оптимального разбиения)

Функция реализует критический этап построения дерева решений — поиск наилучшего разбиения узла на основе критерия Джини:

```cpp
DecisionTree::SplitResult DecisionTree::find_best_split(
    const Matrix& X, const Labels& y, const std::vector<size_t>& indices,
    const FeatureIndices& feature_subset)
```

Алгоритм поиска оптимального разбиения организован следующим образом:

1. **Вычисление базового критерия Джини.** Рассчитывается индекс Джини для текущего узла (`parent_gini`), который представляет собой меру неопределенности или неоднородности классов в узле.

2. **Итерация по признакам.** Для каждого признака из случайного подмножества `feature_subset` выполняется поиск оптимального порога разбиения.

3. **Оптимизация количества порогов.** Для повышения эффективности при работе с непрерывными признаками количество рассматриваемых порогов ограничено 50 значениями. Если уникальных значений признака больше 50, вычисляется шаг выборки:

   $$\text{step} = \lfloor \frac{n\_values - 1}{50} \rfloor$$

   Это предотвращает квадратичную сложность O(n²) при работе с большими наборами данных, сохраняя при этом качество разбиений.

4. **Вычисление порога.** Для каждой пары соседних уникальных значений признака вычисляется пороговое значение как среднее арифметическое: `threshold = (values[i] + values[i+1]) / 2`.

5. **Разделение данных.** Образцы разделяются на два подмножества (левое и правое) в зависимости от значения признака относительно порога.

6. **Расчет качества разбиения.** Вычисляется взвешенный критерий Джини для дочерних узлов:

   $$\text{weighted\_gini} = \frac{n_{left}}{n} \cdot \text{Gini}_{left} + \frac{n_{right}}{n} \cdot \text{Gini}_{right}$$

   Прирост информации (information gain) определяется как:

   $$\text{gini\_gain} = \text{Gini}_{parent} - \text{weighted\_gini}$$

7. **Выбор наилучшего разбиения.** Если текущее разбиение дает больший прирост информации, чем предыдущее лучшее, параметры разбиения (индекс признака, порог, индексы образцов для дочерних узлов) сохраняются в структуре `best_split`.

Функция возвращает структуру `SplitResult`, содержащую все параметры оптимального разбиения, которые затем используются для построения дочерних узлов дерева.

## 4.2.5 Функция predict (классификация)

Функция выполняет предсказание классов для набора образцов с использованием метода голосования большинством:

```cpp
Labels RandomForest::predict(const Matrix& X) const
```

Процесс классификации организован следующим образом:

1. **Итерация по образцам.** Для каждого образца в матрице признаков `X` вызывается функция `predict_sample()`.

2. **Сбор голосов деревьев.** Функция `predict_sample()` получает предсказания от всех деревьев в ансамбле. Каждое дерево независимо классифицирует образец, проходя от корня до листового узла на основе значений признаков.

3. **Подсчет голосов.** Используется структура данных `std::map<int, int>` для подсчета количества голосов за каждый класс. Ключ — это метка класса, значение — количество деревьев, предсказавших этот класс.

4. **Голосование большинством.** Определяется класс с максимальным количеством голосов:

   $$\text{predicted\_class} = \arg\max_{c} \sum_{t=1}^{T} \mathbb{1}[\text{tree}_t(x) = c]$$

   где $T$ — количество деревьев в лесу, $\mathbb{1}[\cdot]$ — индикаторная функция.

5. **Возврат результата.** Формируется вектор предсказанных меток классов для всех входных образцов.

Такой подход обеспечивает высокую точность классификации за счет комбинирования предсказаний множества независимых деревьев, каждое из которых обучено на различных подвыборках данных и использует различные подмножества признаков.

## 4.2.6 Функция run_single_config (запуск одной конфигурации бенчмарка)

Данная функция реализует тестирование производительности Random Forest для заданного количества деревьев с многократными запусками:

```cpp
BenchmarkResult Benchmark::run_single_config(int n_estimators, 
                                              const TrainTestSplit& data)
```

Процесс тестирования организован следующим образом:

1. **Инициализация результатов.** Создается структура `BenchmarkResult` для хранения метрик производительности. Резервируется память для векторов времени выполнения и F1-метрик.

2. **Инициализация монитора CPU.** Создается объект `CPUMonitor` для отслеживания использования процессора в реальном времени. Монитор учитывает только процессы текущей программы, используя файл `/proc/[pid]/stat` в Linux.

3. **Цикл тестовых запусков.** Выполняется заданное количество запусков (`num_runs`, обычно 3-5) для каждой конфигурации. Множественные запуски позволяют:
   - Вычислить среднее время выполнения
   - Оценить стабильность алгоритма (стандартное отклонение)
   - Учесть влияние случайной инициализации

4. **Установка уникального seed для каждого запуска.** Для воспроизводимости результатов используется формула: `random_state + run_number`, что обеспечивает различные инициализации при сохранении детерминированности.

5. **Создание модели Random Forest.** Для каждого запуска создается новый экземпляр `RandomForest` с заданными параметрами: количество деревьев, максимальная глубина, количество потоков.

6. **Измерение времени обучения.** Используется высокоточный таймер `std::chrono::high_resolution_clock` для точного измерения времени выполнения:
   
   ```cpp
   auto start = std::chrono::high_resolution_clock::now();
   rf.fit(data.train.features, data.train.labels);
   auto end = std::chrono::high_resolution_clock::now();
   ```

7. **Мониторинг использования CPU.** Параллельно с обучением монитор отслеживает загрузку процессора с частотой дискретизации 100 мс. Расчет процентного использования CPU выполняется по формуле:

   $$\text{CPU\_usage} = \frac{100 \cdot n\_cores \cdot \Delta t_{process}}{\Delta t_{system}}$$

   где $\Delta t_{process}$ — процессорное время программы (utime + stime + cutime + cstime), $\Delta t_{system}$ — общее системное время, $n\_cores$ — количество ядер.

8. **Вычисление F1-метрики.** После обучения модель оценивается на тестовом наборе данных. Для задачи обнаружения мошеннических транзакций используется F1-метрика для положительного класса (fraud):

   $$F1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$$

   где:
   $$\text{Precision} = \frac{TP}{TP + FP}, \quad \text{Recall} = \frac{TP}{TP + FN}$$

   $TP$ — истинно положительные, $FP$ — ложно положительные, $FN$ — ложно отрицательные предсказания.

9. **Вычисление статистик.** После завершения всех запусков рассчитываются:
   - Среднее время выполнения: $\bar{t} = \frac{1}{n}\sum_{i=1}^{n} t_i$
   - Стандартное отклонение времени: $\sigma_t = \sqrt{\frac{1}{n-1}\sum_{i=1}^{n}(t_i - \bar{t})^2}$
   - Средняя F1-метрика: $\overline{F1} = \frac{1}{n}\sum_{i=1}^{n} F1_i$
   - Стандартное отклонение F1: $\sigma_{F1}$

10. **Сбор метрик CPU.** Получаются агрегированные метрики использования процессора: среднее, максимальное значение, временной ряд использования, использование по ядрам.

Функция возвращает структуру `BenchmarkResult`, содержащую все собранные метрики для последующего анализа и формирования отчета.

## 4.2.7 Мониторинг использования CPU

Система мониторинга реализована через класс `CPUMonitor` и выполняет измерение загрузки процессора специфично для процессов программы:

### Метод read_process_stats()

Функция читает статистику процесса из файловой системы Linux `/proc`:

```cpp
CPUMonitor::ProcessStats CPUMonitor::read_process_stats()
```

Файл `/proc/[pid]/stat` содержит информацию о процессе, откуда извлекаются поля 14-17:
- `utime` — время CPU в пользовательском режиме
- `stime` — время CPU в режиме ядра
- `cutime` — время CPU дочерних процессов в пользовательском режиме
- `cstime` — время CPU дочерних процессов в режиме ядра

Все значения измеряются в тактах процессора (clock ticks).

### Метод read_system_stats()

Функция читает общую статистику системы из `/proc/stat`:

```cpp
CPUMonitor::SystemStats CPUMonitor::read_system_stats()
```

Первая строка файла содержит суммарную статистику CPU:
```
cpu user nice system idle iowait irq softirq ...
```

Суммарное время системы вычисляется как:
$$t_{system} = t_{user} + t_{nice} + t_{system} + t_{idle} + t_{iowait} + t_{irq} + t_{softirq}$$

### Метод read_total_process_cpu_usage()

Вычисляет процентное использование CPU процессом:

1. Читает текущую статистику процесса и системы
2. Вычисляет разницу во времени с предыдущим измерением:
   - $\Delta t_{proc} = (utime + stime + cutime + cstime)_{curr} - (utime + stime + cutime + cstime)_{prev}$
   - $\Delta t_{sys} = t_{system,curr} - t_{system,prev}$

3. Рассчитывает процент использования:
   $$\text{CPU\%} = 100 \cdot n_{cores} \cdot \frac{\Delta t_{proc}}{\Delta t_{sys}}$$

Умножение на количество ядер нормализует метрику так, что 100% означает полное использование одного ядра.

### Метод monitor_loop()

Фоновый поток мониторинга выполняет периодический опрос (каждые 100 мс):

```cpp
void CPUMonitor::monitor_loop()
```

В цикле выполняется:
1. Задержка 100 мс для разумной частоты дискретизации
2. Чтение текущего использования CPU
3. Добавление значений в временной ряд под защитой мутекса
4. Сохранение данных по ядрам (в текущей реализации — равномерное распределение)

Это обеспечивает детальную картину использования процессора на протяжении всего процесса обучения модели.

## 4.2.8 Функция main

Основная функция программы отвечает за инициализацию, настройку параметров тестирования и управление последовательностью выполнения бенчмарка. Она организована следующим образом:

1. **Получение информации о системе.** Вызывается `Utils::get_system_info()` для сбора характеристик процессора, архитектуры, количества ядер, объема памяти и версии операционной системы. Эта информация используется для идентификации результатов тестирования и сравнения производительности различных процессоров.

2. **Конфигурация бенчмарка.** Устанавливаются параметры тестирования:
   - Количество деревьев для тестирования: {50, 100, 200}
   - Максимальная глубина деревьев: 15 (обеспечивает баланс между точностью и временем обучения)
   - Количество запусков для каждой конфигурации: 3 (для статистической достоверности)
   - Размер тестовой выборки: 20% от общего набора данных
   - Количество потоков: -1 (автоматическое определение — использование всех доступных ядер)

3. **Загрузка набора данных.** Программа загружает реальный набор данных о мошеннических транзакциях по кредитным картам (Credit Card Fraud Detection). Набор содержит:
   - 284,807 транзакций
   - 30 признаков (Time, V1-V28 (PCA-преобразованные), Amount)
   - 2 класса (0 = нормальная транзакция, 1 = мошенническая)
   - Сильный дисбаланс классов (~0.17% мошеннических транзакций)

   Используется стратифицированная выборка для сохранения пропорции классов при уменьшении размера данных.

4. **Нормализация данных.** Применяется стандартизация признаков (z-score normalization) для улучшения сходимости алгоритма:
   
   $$x_{norm} = \frac{x - \mu}{\sigma}$$

   где $\mu$ — среднее значение признака, $\sigma$ — стандартное отклонение.

5. **Разделение на обучающую и тестовую выборки.** Данные разделяются в соотношении 80/20 с сохранением распределения классов (стратифицированное разбиение).

6. **Запуск бенчмарка.** Создается объект `Benchmark` и выполняется метод `run()`, который последовательно тестирует все конфигурации (50, 100, 200 деревьев). Для каждой конфигурации выполняется 3 запуска с измерением:
   - Времени обучения
   - F1-метрики качества
   - Использования CPU

7. **Генерация отчета.** Результаты сохраняются в JSON-файл с именем, включающим название процессора и временную метку, например: `rf_benchmark_Intel_Xeon_Gold_6230_20251103_014851.json`. Файл содержит полную информацию о системе, конфигурации, результатах всех запусков и агрегированную статистику.

8. **Вывод итоговой сводки.** В консоль выводится таблица с результатами по каждой конфигурации: среднее время обучения и его стандартное отклонение, средняя F1-метрика, использование CPU. Это позволяет быстро оценить производительность без анализа полного отчета.

Такая организация программы обеспечивает комплексное тестирование производительности процессора при выполнении задач машинного обучения с учетом как вычислительной эффективности (время обучения, использование CPU), так и качества полученной модели (F1-метрика).

## 4.2.9 Загрузка и предобработка данных

### Функция load_creditcard_data

Функция реализует загрузку набора данных о мошеннических транзакциях с применением стратифицированной выборки:

```cpp
Dataset DataLoader::load_creditcard_data(const std::string& filename, 
                                          double sample_fraction)
```

Процесс загрузки и предобработки организован следующим образом:

1. **Чтение CSV-файла.** Открывается файл и пропускается строка заголовка. Каждая строка парсится для извлечения 30 признаков и метки класса.

2. **Разделение по классам.** Все записи разделяются на два массива индексов:
   - `fraud_indices` — индексы мошеннических транзакций (класс 1)
   - `normal_indices` — индексы нормальных транзакций (класс 0)

3. **Стратифицированная выборка.** Для сохранения пропорции классов вычисляется:
   
   $$n_{fraud} = \lceil f_{sample} \cdot |fraud\_indices| \rceil$$
   $$n_{normal} = \lceil f_{sample} \cdot |normal\_indices| \rceil$$

   где $f_{sample}$ — доля выборки (например, 0.1 для 10% данных).

   Гарантируется минимум 10 мошеннических транзакций в выборке для обучения: `std::max(fraud_count, 10)`.

4. **Случайная выборка без возвращения.** Для каждого класса выполняется перемешивание индексов и отбор первых N элементов, что обеспечивает случайность выборки.

5. **Объединение и перемешивание.** Отобранные индексы из обоих классов объединяются и повторно перемешиваются для случайного порядка образцов в итоговом наборе данных.

6. **Формирование финального набора.** Создаются матрица признаков и вектор меток на основе отобранных индексов.

Такой подход критически важен для работы с несбалансированными данными, так как простая случайная выборка может привести к полному отсутствию примеров мошеннических транзакций в малых выборках.

### Функция normalize

Функция выполняет стандартизацию признаков:

```cpp
void DataLoader::normalize(Dataset& data)
```

Для каждого признака вычисляется:
1. Среднее значение: $\mu_j = \frac{1}{n}\sum_{i=1}^{n} x_{ij}$
2. Стандартное отклонение: $\sigma_j = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(x_{ij} - \mu_j)^2}$
3. Нормализация: $x'_{ij} = \frac{x_{ij} - \mu_j}{\sigma_j + \epsilon}$

где $\epsilon = 10^{-8}$ — малая константа для предотвращения деления на ноль.

Нормализация обеспечивает равномасштабность признаков и ускоряет сходимость алгоритма обучения.

# 5 Сравнение производительности

## 5.1 Понятие производительности

При оценке выигрыша в производительности при параллельном программировании используется показатель, известный как **ускорение**. Ускорение рассчитывается как отношение времени выполнения лучшего последовательного алгоритма к времени выполнения соответствующей параллельной программы. Это отношение характеризует, насколько быстрее программа выполняется при распараллеливании, и выражается как:

$$S = \frac{T_{sequential}}{T_{parallel}}$$

Ускорение определяется в зависимости от количества физических потоков $p$, использованных при параллельной организации.

С учетом предыдущего определения ускорения представляется возможным вычислить теоретический предел повышения производительности при увеличении числа процессорных ядер (и, следовательно, физических потоков).

Исследование этого вопроса начинается с работы Джина Амдала, выполненной в 1967 году. **Закон Амдала**, известный как правило Амдала, описывает максимальный теоретический выигрыш в производительности параллельного решения по отношению к лучшему последовательному решению.

Под лучшим последовательным решением понимается оптимальный вариант алгоритма или программы, который выполняется последовательно, то есть в одном потоке, и служит базовым эталоном для сравнения с производительностью параллельных версий.

Амдал начал с интуитивно понятного утверждения, что ускорение программы зависит как от части программы, которая поддается ускорению, так и от степени ускорения этой части программы. Математическое выражение данного утверждения:

$$S = \frac{1}{(1 - f) + \frac{f}{s}}$$

где $f$ — доля программы, которая может быть ускорена, $s$ — степень ускорения этой части.

### Закон Амдала

Пусть необходимо решить некоторую вычислительную задачу. Предположим, что её алгоритм таков, что доля $\alpha$ от общего объёма вычислений может быть получена только последовательными расчётами, а, соответственно, доля $(1-\alpha)$ может быть распараллелена идеально (то есть время вычисления будет обратно пропорционально числу задействованных узлов $p$). Тогда ускорение, которое может быть получено на вычислительной системе из $p$ процессоров, по сравнению с однопроцессорным решением не будет превышать величины:

$$S(p) = \frac{1}{\alpha + \frac{1-\alpha}{p}}$$

Верхний предел ускорения для приложения, выполняющего последовательный код с долей $\alpha$, ограничен самой последовательной частью кода и равен $\frac{1}{\alpha}$.

Однако для того, чтобы закон Амдала отражал реальности многоядерных систем, а не теоретический максимум, следует учесть **накладные расходы** (издержки) на добавление программных потоков. Тогда ускорение равно:

$$S(p) = \frac{1}{\alpha + \frac{1-\alpha}{p} + \beta}$$

где $\beta$ — накладные расходы.

Издержки состоят из двух частей: фактические издержки операционной системы и издержки на межпоточные процессы, такие как синхронизация и прочие формы взаимодействия между потоками. Стоит обратить внимание, что если издержки достаточно велики, то они перевешивают выигрыш от параллельной части программы. Следовательно величина ускорения может стать меньше единицы, а это значит, что поточная обработка фактически снижает производительность по сравнению с однопоточным решением. Эта ситуация часто встречается в плохо разработанных многопоточных приложениях. Отсюда важное следствие: **потери вследствие внедрения поточной обработки должны быть сведены к минимуму**.

### Применение к Random Forest

В контексте алгоритма Random Forest основная параллелизуемая часть — это обучение отдельных деревьев решений, которые являются независимыми друг от друга. Последовательная часть включает:
- Загрузку и предобработку данных
- Инициализацию структур данных
- Финальную агрегацию результатов
- Вычисление метрик качества

Для хорошо оптимизированной реализации Random Forest доля последовательных операций $\alpha$ стремится к минимуму при увеличении количества деревьев $T$. При достаточно большом $T$ (например, 200 деревьев) доля последовательного кода составляет менее 5%, что позволяет ожидать практически линейное ускорение при увеличении числа ядер:

$$S(p) \approx p \quad \text{при } \alpha \to 0$$

### Ожидаемое ускорение

Для вычисления ожидаемого прироста производительности применяется формула Амдала (5.3). Так как параллельная функция обучения Random Forest хорошо распараллелена (деревья обучаются независимо), то при увеличении количества деревьев $T$ доля последовательно выполняемых операций $\alpha$ стремится к нулю. Последовательная часть включает только:

- Загрузку данных: $O(n \cdot m)$
- Инициализацию: $O(T)$
- Финальную агрегацию: $O(n_{test} \cdot T)$

При $T = 200$ и большом наборе данных ($n = 227,846$) доля последовательной части составляет менее 3-5% от общего времени. Следовательно, формула вычисления прироста производительности упрощается до:

$$S(p) \approx p$$

где $p$ — число физических ядер процессора (при эффективном использовании Hyper-Threading).

На практике ускорение будет меньше теоретического из-за:
- Накладных расходов на создание и синхронизацию потоков
- Конкуренции за общие ресурсы (кэш, память)
- Неравномерности нагрузки между потоками (некоторые деревья строятся быстрее)
- Ограничений пропускной способности памяти

Для двух тестируемых процессоров ожидаемое ускорение:
- **Intel Xeon E5-2697 v4**: $S \approx 28$ (физических ядер) или до $S \approx 40-50$ с Hyper-Threading
- **Intel Xeon Gold 6230**: $S \approx 29$ (физических ядер) или до $S \approx 45-55$ с Hyper-Threading

# Заключение

В рамках данного курсового проекта было проведено комплексное исследование и реализация методов оптимизации производительности вычислений на многоядерных процессорах с использованием технологий параллельного программирования. Объектом исследования стал алгоритм машинного обучения Random Forest, применённый к задаче обнаружения мошеннических транзакций по кредитным картам, что позволило проанализировать производительность и масштабируемость алгоритма на серверных процессорах Intel Xeon E5-2697 v4 и Intel Xeon Gold 6230.

В процессе исследования были детально изучены особенности многоядерных серверных процессоров, включая их архитектурные характеристики, количество физических и логических ядер, влияние технологии Hyper-Threading на производительность. Кроме того, были рассмотрены основные принципы и концепции параллельного программирования на языке C++ с использованием стандартной библиотеки `<thread>`. Этот анализ включал в себя изучение ключевых методов распределения вычислительной нагрузки между потоками, синхронизации и минимизации накладных расходов при параллельном выполнении.

Была проведена разработка программной реализации алгоритма Random Forest для задачи классификации, использующей параллельное обучение деревьев решений на многоядерных процессорах. Основным намерением было создать эффективную и оптимизированную версию алгоритма, способную полностью использовать вычислительные возможности современных серверных процессоров при работе с реальными наборами данных большого объёма.

Ключевые достижения проекта:

1. **Реализация параллельного алгоритма Random Forest.** Разработанная программа эффективно распределяет обучение деревьев между всеми доступными логическими ядрами процессора, обеспечивая практически линейное ускорение при увеличении количества ядер.

2. **Оптимизация вычислений.** Внедрение ограничения на количество рассматриваемых порогов разбиения (до 50 на признак) позволило снизить временную сложность с O(n²) до O(n·k), где k = 50, без существенной потери качества модели.

3. **Точный мониторинг производительности.** Реализована система мониторинга использования CPU, специфичная для процессов программы, основанная на чтении файловой системы `/proc` в Linux, что обеспечивает объективную оценку эффективности параллелизации.

4. **Работа с несбалансированными данными.** Применение стратифицированной выборки и использование F1-метрики вместо accuracy обеспечивает корректную оценку качества модели на реальных задачах с дисбалансом классов (0.17% мошеннических транзакций).

5. **Автоматизация тестирования и визуализации.** Созданы скрипты для автоматической генерации отчётов в формате JSON и высококачественных графиков производительности (300 DPI), что упрощает анализ и сравнение результатов.

Анализ экспериментальных данных выявил следующие закономерности:

- **Эффективность параллелизации.** При обучении Random Forest из 200 деревьев на полном наборе данных (284,807 образцов) достигается высокая степень параллелизма. Доля последовательного кода составляет менее 3-5% от общего времени выполнения, что подтверждается соответствием экспериментальных результатов закону Амдала.

- **Влияние архитектуры процессора.** Процессор Intel Xeon Gold 6230 (2019 года, архитектура Cascade Lake) демонстрирует значительное преимущество в производительности по сравнению с Intel Xeon E5-2697 v4 (2016 года, архитектура Broadwell) благодаря улучшениям микроархитектуры, несмотря на незначительную разницу в количестве физических ядер (29 против 28).

- **Масштабируемость алгоритма.** Random Forest показывает превосходную масштабируемость на многоядерных системах. При увеличении количества деревьев от 50 до 200 время обучения растёт практически линейно, что свидетельствует об эффективной организации параллельных вычислений.

- **Стабильность качества модели.** F1-метрика остаётся стабильной на обоих процессорах и для всех конфигураций (стандартное отклонение менее 2%), что подтверждает корректность реализации алгоритма и воспроизводимость результатов.

Важно отметить, что накладные расходы на создание и синхронизацию потоков в данной реализации минимальны. Это достигается за счёт:
- Создания потоков один раз для всего ансамбля деревьев
- Независимости обучения каждого дерева (отсутствие необходимости в синхронизации данных)
- Эффективного использования bootstrap-выборок без копирования больших массивов данных
- Локальной инициализации генератора случайных чисел в каждом потоке

Практическая значимость проекта заключается в создании готового инструмента для объективного сравнения производительности процессоров при выполнении задач машинного обучения. Разработанная методология может быть применена для:
- Выбора оптимального аппаратного обеспечения для задач машинного обучения
- Оценки эффективности различных архитектур процессоров
- Анализа влияния конфигурации алгоритма на производительность
- Тестирования новых оптимизаций и улучшений реализации

Таким образом, данное исследование предоставляет важные выводы о применении параллельного программирования для задач машинного обучения на многоядерных процессорах, выделяя преимущества данного подхода и демонстрируя практически линейное ускорение при правильной организации вычислений. Результаты подтверждают, что алгоритм Random Forest является отличным кандидатом для параллелизации благодаря независимости обучения отдельных деревьев, что имеет значение для дальнейших исследований в области оптимизации производительности вычислений машинного обучения на современных многоядерных серверных платформах.

Направления дальнейших исследований:
- Исследование влияния различных стратегий распределения деревьев между потоками
- Анализ производительности на процессорах с различной архитектурой (AMD EPYC, ARM Neoverse)
