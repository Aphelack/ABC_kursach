# Руководство по анализу масштабируемости Random Forest

## Обзор

Этот набор инструментов предназначен для комплексного анализа масштабируемости параллельной реализации Random Forest. Инструменты позволяют проводить три основных типа экспериментов и автоматически генерировать графики для анализа.

## Структура экспериментов

### 1. Масштабируемость по числу потоков (`config_scalability_threads.json`)

**Цель**: Измерить, как изменяется время обучения и эффективность при увеличении числа потоков.

**Параметры**:
- Фиксированное количество деревьев: 100
- Переменное число потоков: 1, 2, 4, 8, 16, 32, -1 (все ядра)
- Количество запусков: 5 (для статистической достоверности)

**Что измеряется**:
- Время обучения T(p) для каждого p (число потоков)
- Ускорение: S(p) = T(1) / T(p)
- Эффективность: E(p) = S(p) / p
- Загрузка CPU
- F1-score (для проверки, что качество не меняется)

### 2. Масштабируемость по числу деревьев (`config_scalability_estimators.json`)

**Цель**: Проверить линейную масштабируемость по объёму работы.

**Параметры**:
- Фиксированное число потоков: -1 (все ядра)
- Переменное количество деревьев: 25, 50, 100, 200, 400
- Количество запусков: 5

**Что измеряется**:
- Время обучения для каждого количества деревьев
- Время на одно дерево (должно быть примерно константой)
- F1-score (как меняется качество)

### 3. Масштабируемость по размеру датасета (`config_scalability_dataset.json`)

**Цель**: Проверить, как алгоритм масштабируется по размеру входных данных.

**Параметры**:
- Фиксированное число потоков: -1 (все ядра)
- Фиксированное количество деревьев: 100
- Переменный размер датасета: 10%, 25%, 50%, 75%, 100%

**Примечание**: Для этого эксперимента требуется модификация кода для загрузки части датасета.

## Быстрый старт

### 1. Запуск всех экспериментов

```bash
chmod +x run_scalability.sh
./run_scalability.sh
```

Этот скрипт:
- Запустит все эксперименты последовательно
- Сохранит результаты в директорию `scalability_results_<timestamp>/`
- Автоматически сгенерирует графики (если установлен Python с matplotlib)

### 2. Запуск отдельных экспериментов

```bash
# Эксперимент 1: Масштабируемость по потокам
./build/rf_benchmark ../dataset/creditcard.csv config_scalability_threads.json

# Эксперимент 2: Масштабируемость по деревьям
./build/rf_benchmark ../dataset/creditcard.csv config_scalability_estimators.json
```

### 3. Анализ результатов

```bash
# Анализ одного эксперимента
python3 scalability_analysis.py rf_benchmark_<timestamp>.json

# Указать директорию для графиков
python3 scalability_analysis.py report.json --output-dir my_analysis

# Сравнение нескольких процессоров
python3 compare_scalability.py report_cpu1.json report_cpu2.json --output-dir comparison
```

## Использование результатов в курсовой работе

### Раздел "Анализ масштабируемости"

Используйте сгенерированные графики и данные для написания раздела:

1. **Ускорение и эффективность**:
   - Покажите график speedup_vs_threads.png
   - Опишите, до какого числа потоков ускорение близко к линейному
   - Объясните точку насыщения и причины падения эффективности

2. **Связь с законом Амдала**:
   - Используйте оценку последовательной доли из отчёта
   - Покажите, как кривая ускорения соответствует предсказаниям Амдала
   - Обсудите ограничения параллелизма

3. **Масштабируемость по объёму работы**:
   - Используйте график time_vs_estimators.png
   - Покажите, что время растёт линейно с числом деревьев
   - Обсудите, что качество (F1) стабильно или улучшается незначительно

4. **Сравнение процессоров**:
   - Используйте comparison_*.png графики
   - Обсудите архитектурные различия процессоров
   - Объясните, почему один процессор эффективнее другого

### Типичные формулировки для текста

```
На рисунке X представлена зависимость ускорения от числа потоков для процессора

Это означает, что теоретическое максимальное ускорение ограничено величиной

```

## Требования

### Python пакеты:
```bash
pip install -r requirements.txt
```

Основные зависимости:
- matplotlib >= 3.5.0
- seaborn >= 0.12.0
- numpy >= 1.21.0

### Система:
- C++17 компилятор (g++ или clang++)
- CMake >= 3.15
- Достаточно RAM для загрузки датасета

## Советы по проведению экспериментов

1. **Минимизируйте фоновую активность**: Закройте ненужные программы перед запуском

2. **Запускайте несколько раз**: Используйте `num_runs: 5` для получения статистики

3. **Проверяйте температуру**: При длительных тестах следите, чтобы не было троттлинга

4. **Документируйте окружение**: Сохраните информацию о:
   - Версии ОС и ядра
   - Настройках CPU governor (performance vs powersave)
   - Других запущенных процессах

5. **Экспериментируйте с параметрами**:
   - Попробуйте разные `max_depth` (10, 15, 20)
   - Варьируйте размер датасета
   - Тестируйте разные паттерны потоков (1, 2, 4, 8, ...)

## Расширенные эксперименты (опционально)

### Влияние NUMA
Если процессор имеет несколько NUMA-узлов:
```bash
# Запуск на одном NUMA-узле
numactl --cpunodebind=0 --membind=0 ./build/rf_benchmark ...

# Запуск на всех NUMA-узлах
numactl --interleave=all ./build/rf_benchmark ...
```

### Влияние частоты CPU
```bash
# Установить максимальную частоту
sudo cpupower frequency-set -g performance

# Вернуть автоматическое управление
sudo cpupower frequency-set -g ondemand
```

## Устранение неполадок

**Проблема**: Графики не генерируются
- Решение: Проверьте установку matplotlib: `pip3 install matplotlib seaborn`

**Проблема**: Мало данных для анализа
- Решение: Убедитесь, что в конфиге достаточно вариаций параметров (минимум 3-4 точки)

**Проблема**: Большой разброс результатов
- Решение: Увеличьте `num_runs` в конфиге до 7-10 запусков

**Проблема**: Benchmark падает с ошибкой памяти
- Решение: Уменьшите `n_estimators` или используйте меньший датасет
